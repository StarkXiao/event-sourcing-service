# 项目文档：事件溯源与投影视图服务

## 1. 项目概述

本项目使用 Go 构建一个可持久化的事件溯源服务（Event Sourcing Service）。系统以不可变的领域事件作为业务事实来源，通过事件存储恢复聚合状态，异步生成查询投影视图，并提供事件重放、投影重建和一致性核验能力。项目必须使用真实数据库持久化，不能使用仅存在于进程内存的示例实现。

服务面向订单、账户、库存等需要完整审计轨迹的业务场景。写入端只追加事件，不直接修改历史；读取端通过投影表提供高效查询。系统需要在重启、重复投递、投影失败、版本冲突和部分重放等情况下保持可恢复、可观测和可验证。

## 2. 建设目标与非目标

### 2.1 建设目标

1. 提供带聚合版本控制的事件追加能力，防止并发写入覆盖。
2. 保存事件的租户、聚合、序列号、类型、载荷、元数据和时间信息。
3. 根据事件异步构建订单摘要、账户余额等投影视图。
4. 支持按聚合、事件类型、时间范围和全局位置查询事件。
5. 支持从指定版本或指定时间点重放，并将投影安全切换到新版本。
6. 支持事件流与投影视图之间的校验，输出差异明细。
7. 提供数据库迁移、配置校验、结构化日志、指标和健康检查。
8. 提供可重复的单元测试、集成测试和端到端验证脚本。

### 2.2 非目标

本期不实现跨区域多主复制、通用 CQRS 编排平台、任意用户脚本执行、分布式事务协调器和面向外部客户的计费系统。领域聚合以订单和账户为首个示例，但存储与投影接口要保持可扩展。

## 3. 核心业务功能

### 3.1 订单生命周期

订单创建时产生 `OrderCreated` 事件，包含订单号、买家、币种和初始金额。订单只能从 `pending` 进入 `paid`、`cancelled` 或 `expired`。支付成功产生 `OrderPaid`，取消产生 `OrderCancelled`，超时关闭产生 `OrderExpired`。已支付订单不能被普通取消；重复支付必须返回幂等成功而不能追加第二条事实事件；已取消或已过期订单拒绝支付。

### 3.2 账户余额

账户开户产生 `AccountOpened`，入账和扣款分别产生 `MoneyCredited` 与 `MoneyDebited`。余额不能为负，扣款必须校验可用余额和币种。相同业务幂等键重复提交时返回第一次提交的结果。账户事件按账户聚合顺序追加，余额投影保存当前余额、累计入账和累计扣款。

### 3.3 事件追加与版本

每个聚合拥有从 1 开始递增的版本号。客户端提交 `expected_version`：新聚合必须为 0，更新必须等于当前版本。数据库在同一事务中锁定聚合版本、校验序列号、写入事件和更新聚合头；冲突返回 409，并带当前版本。事件写入成功后发布可靠的投影任务，不允许因投影暂时失败而回滚已提交事实。

### 3.4 查询与一致性

查询 API 默认读取最近一次成功投影的数据，并返回 `projection_version`、`event_version` 和滞后量。需要强一致的调用方可指定 `min_version`，服务在超时前等待投影追平，超时返回明确的未追平状态。事件查询为只读操作，结果支持游标分页，游标必须包含租户、过滤条件和最后全局位置，避免跨条件复用。

## 4. 业务流程

### 4.1 写入流程

1. HTTP 请求经过请求 ID、租户和身份中间件。
2. 参数层校验 UUID、金额精度、事件类型白名单和幂等键。
3. 应用服务加载聚合事件并折叠为当前状态。
4. 领域层执行状态迁移，生成一个或多个新事件。
5. 仓储层开启事务，检查幂等记录和 `expected_version`。
6. 追加事件、更新聚合头、写入 outbox 任务并提交事务。
7. 返回事件版本和聚合状态摘要；投影异步追赶。

### 4.2 投影流程

后台调度器按租户和投影名称拉取待处理任务，使用数据库租约避免多实例重复消费。每个任务在事务内读取连续事件，调用投影处理器更新视图并写入检查点。成功后确认任务；失败时记录错误、增加退避重试次数，超过上限进入死信表。处理器必须按事件 ID 幂等，重复消费不能产生重复金额或重复行。

### 4.3 重放流程

管理员创建重放作业，指定租户、聚合范围、起始全局位置、目标位置和投影名称。系统为该投影创建带作业版本的临时表，从事件存储按顺序扫描，重建临时视图并持续写入检查点。重放完成后执行校验，只有校验通过才能原子地切换视图别名；旧视图保留一段可配置的回滚窗口。

### 4.4 一致性核验流程

核验器重新折叠指定聚合的事件，计算理论状态摘要，与投影表的版本、状态字段和金额字段逐项比较。结果分为一致、版本落后、数据差异、事件缺失和投影错误。核验明细写入审计表，可按作业分页查询；修复动作只能触发重放，不允许直接修改事件或投影数据。

## 5. 系统分层与模块边界

采用清晰的分层结构，依赖方向由外向内：

- `cmd/server`：进程启动、配置加载、依赖装配、优雅退出。
- `internal/config`：环境变量和配置文件解析、默认值、敏感字段校验。
- `internal/domain`：订单、账户聚合；状态、命令、领域事件和不变量。
- `internal/application`：写入、查询、重放、核验用例；事务边界和权限策略。
- `internal/eventstore`：事件追加、聚合加载、全局扫描、幂等和 outbox 仓储接口。
- `internal/projection`：投影处理器、调度器、租约、重试、死信和检查点。
- `internal/replay`：作业生命周期、临时表、切换和回滚。
- `internal/consistency`：折叠器、摘要计算、差异分类和报告。
- `internal/transport/http`：路由、请求/响应 DTO、错误映射、分页和中间件。
- `internal/platform`：数据库连接、迁移执行、日志、指标、时钟和 ID 生成器。

领域包不得依赖 HTTP、SQL 驱动或具体日志实现；应用层依赖接口；基础设施层实现接口。公共错误需包含稳定错误码、可读消息和可选字段，禁止将数据库原始错误直接返回客户端。

## 7. 数据库设计与迁移

使用 PostgreSQL 作为持久化数据库，所有表通过有序迁移创建，迁移必须支持向前执行并记录版本。

### 7.1 `events`

字段包括：`id`（UUID 主键）、`tenant_id`、`aggregate_type`、`aggregate_id`、`aggregate_version`、`event_type`、`payload`（JSONB）、`metadata`（JSONB）、`occurred_at`、`global_position`（BIGSERIAL）和 `idempotency_key`。唯一约束为租户+聚合+版本，租户+幂等键；按租户、聚合和全局位置建立索引。

### 7.2 `aggregate_heads`

保存租户、聚合类型、聚合 ID、当前版本和最后事件时间。租户+类型+ID 为主键。追加事件时使用 `SELECT ... FOR UPDATE` 锁定该行，避免并发版本穿透。

### 7.3 `projection_checkpoints`

保存投影名称、租户、最后处理全局位置、最后事件版本、状态、错误信息、更新时间和租约字段。租户+投影名称唯一。

### 7.4 `outbox_tasks` 与 `dead_letters`

outbox 记录待投影的事件 ID、目标投影、状态、尝试次数、下次执行时间和锁定时间；死信记录最终错误、原始任务和人工处置状态。二者都需要按状态和时间建立调度索引。

### 7.5 业务投影表

`order_views` 保存订单摘要、金额、状态、买家和投影版本；`account_views` 保存余额、累计入账、累计扣款和投影版本。重放使用带作业后缀的临时表，并通过数据库视图或别名完成切换。

### 7.6 迁移要求

至少提供初始化、索引与约束、投影表、outbox/死信、核验审计表五组迁移。应用启动时只执行明确配置允许的迁移检查，生产环境禁止无提示自动降级或删除字段。

## 8. HTTP API 约定

- `POST /v1/aggregates/{type}/{id}/commands`：执行领域命令。请求包含 `command_type`、参数、`expected_version` 和 `idempotency_key`。
- `GET /v1/aggregates/{type}/{id}/events`：按版本游标查询事件，可指定 `from_version`、`to_version` 和 `limit`。
- `GET /v1/events`：按事件类型、租户、时间范围和全局位置过滤。
- `GET /v1/views/orders/{id}`：查询订单投影视图，支持 `min_version`。
- `GET /v1/views/accounts/{id}`：查询账户投影视图，支持 `min_version`。
- `POST /v1/projections/{name}/replay`：创建重放作业，仅管理员可用。
- `GET /v1/replays/{job_id}`：查询重放进度、错误和校验结果。
- `POST /v1/consistency/checks`：创建一致性核验作业。
- `GET /v1/consistency/checks/{job_id}`：查询核验摘要和差异。
- `GET /health/live`、`GET /health/ready`：进程存活与数据库/投影依赖就绪检查。

统一返回 `request_id`、`data` 或 `error`。错误码至少包括 `INVALID_ARGUMENT`、`CONFLICT`、`NOT_FOUND`、`IDEMPOTENCY_REPLAY`、`PROJECTION_LAG`、`REPLAY_RUNNING` 和 `INTERNAL_ERROR`。列表接口使用 `items`、`next_cursor`、`has_more`，并限制最大 page size。

## 9. 异步任务与可靠性

投影 worker 支持并发度配置、按租户公平调度、每批事务大小、租约超时和优雅停止。重试采用指数退避并加入抖动，区分可重试数据库错误和不可重试载荷错误。服务重启后可根据租约过期时间接管任务。outbox 与事件在同一数据库事务中写入，确保事实事件不会因消息发布失败而丢失。

投影处理至少实现事件 ID 去重、版本连续性检查和事务回滚。发现版本跳跃时暂停该聚合并报警，而不是静默覆盖。死信必须可查询、可重试和可标记为已确认。

## 10. 可观测性与安全

日志采用 JSON 结构，包含请求 ID、租户、聚合、事件 ID、投影名称和耗时，不记录敏感载荷。指标至少包括事件追加成功/失败数、冲突数、投影延迟、处理吞吐、重试数、死信数、重放进度和核验差异数。健康检查区分存活与就绪。

所有写接口需要认证和租户隔离；管理员接口需要独立角色。SQL 使用参数化查询，JSON 载荷限制大小，事件类型和聚合类型采用白名单。审计日志记录重放、核验、死信处置和视图切换操作。

## 11. 测试与验证

测试代码不计入 2,050 至 2,150 行生产代码限制，但必须覆盖核心风险：

1. 领域测试：合法/非法状态迁移、金额精度、负余额和重复命令。
2. 事件存储集成测试：事务回滚、版本冲突、幂等约束、分页游标。
3. 投影测试：乱序拒绝、重复事件幂等、失败重试、死信转移和检查点恢复。
4. 重放测试：从零重建、从中间位置重建、校验失败不切换、切换后回滚。
5. API 测试：错误码、认证租户隔离、`min_version` 等待和健康检查。
6. 端到端测试：创建订单、支付、投影追平、查询、重放和一致性核验全流程。

验证命令建议为 `go test ./...`、`go test -race ./...`、`go vet ./...`，并使用临时 PostgreSQL 执行迁移和集成测试。提交前使用脚本统计生产 Go 文件数和有效代码行数，统计时排除 `_test.go`、`vendor`、生成文件和空白行，并将结果写入 CI 日志。

## 12. 验收标准

- 目录包含本项目文档及后续实现所需的迁移、配置示例和运行说明。
- 生产 Go 源文件数量为 21 至 23 个，严格满足大于 20、小于 25。
- 不含测试的有效 Go 代码行为 2,050 至 2,150 行，严格满足大于 2,000、小于 2,200。
- 事件、聚合头、outbox、检查点、投影、重放和核验结果均持久化到 PostgreSQL。
- 服务重启后事件和投影进度可恢复；重复任务不会造成重复业务结果。
- 版本冲突、投影滞后、重放失败和一致性差异都有稳定 API 响应与日志指标。
- 任何修复投影的动作都通过重放完成，原始事件不可更新或删除。

## 13. 后续实现顺序

先完成迁移和平台连接，再实现领域事件与仓储事务；随后接入命令/查询 API、outbox worker 和投影；最后实现重放、核验、观测性、集成测试与代码规模检查。每一步都应保持可启动、可迁移和可回滚，避免先写无法落地的内存演示。
